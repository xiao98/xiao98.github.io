How layer updates move through a GNN: tensor shapes, Transformer depth, and GNN depth

Published on 19 November 2026.

Part 5 of 10 in Questions on StructLoRA (ACL 2026).

Standard LoRA trains each Transformer layer’s adapter independently. In Table 13 (BERT-base on SST-2), StructLoRA reports that the cosine similarity between adjacent layers’ update gradients under vanilla LoRA sits between \(0.27\) and \(0.41\) (mean \(0.34\)), which the authors term structural incoherence. To couple updates across depth, Stage 2 treats the Transformer itself as a graph and passes layer updates through a shallow Graph Neural Network (GCN or GAT).

Two independent notions of “layer”

Reading the paper’s notation requires keeping two orthogonal depth dimensions separate:

  • Transformer depth \(L\) is the number of nodes in the graph \(\mathcal{G} = (\mathcal{V}, \mathcal{E})\)—for example, \(L = 32\) nodes for LLaMA-7B. Node \(\ell \in \{1, \dots, L\}\) represents layer \(\ell\) of the backbone.
  • GNN depth \(T\) is a separate hyperparameter controlling how many rounds of message passing those \(L\) nodes perform with their neighbours during each training step (StructLoRA uses \(T = 1\) by default, and ablates \(T \in \{1, 2, 3\}\)).

Why updates are flattened and reshaped

Each layer \(\ell\) outputs a filtered 2D update matrix \(\Delta \tilde{W}_\ell = A_\ell \operatorname{diag}(m_\ell) B_\ell \in \mathbb{R}^{d \times k}\). Standard GNN layers expect a 1D feature vector per node, so StructLoRA flattens each layer’s matrix into \(h_\ell^{(0)} = \operatorname{vec}(\Delta \tilde{W}_\ell) \in \mathbb{R}^{d_\ell}\) (with \(d_\ell = dk\)), runs \(T\) residual message-passing steps, projects through a linear map \(W_o\), and reshapes the output back into a \(d \times k\) matrix so it can be added element-wise to the frozen weight \(W_{0,\ell}\):

Filtered updates ΔW̃_ℓ     vec()        Node matrix H^(0)      T GNN steps       H^(T)        W_o + reshape()     Final updates ΔW̃_ℓ^final
 L matrices of [d, k]   ─────────▶      [L, d·k]           ──────────────▶    [L, d·k]     ──────────────────▶    L matrices of [d, k]

The graph edges \(\mathcal{E}\) combine two relations (hybrid graph): adjacency edges linking consecutive layers \((\ell, \ell \pm 1)\), and semantic edges linking non-adjacent layers whose batch-averaged update gradients exceed a cosine-similarity threshold. Table 6 shows that combining both edge types (\(81.3\%\) on BoolQ) outperforms adjacency-only (\(80.5\%\)) and similarity-only (\(80.2\%\)).

Crucially, this entire graph pipeline runs only during training. Once training converges, the final updates \(\Delta \tilde{W}_\ell^{\text{final}}\) are merged into \(W_{0,\ell}\) and the GNN is discarded. (Whether the literal \(d_\ell\)-dimensional projection \(W_o\) is computationally tractable at \(d_\ell = 16.8\text{M}\) is a separate question examined in Part 10.)

Takeaway

Transformer depth \(L\) sets the graph size (one node per layer), whereas GNN depth \(T\) sets the number of neighbour-averaging rounds. Flattening adapts 2D weight updates to the GNN’s vector interface, and reshaping restores the matrix layout required to merge into \(W_0\).
