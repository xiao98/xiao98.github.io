Why does GRPO with one rollout work at all?

Published on 22 November 2026.

Search-R1 (Jin et al., COLM 2025) trains an LLM to alternate between reasoning and search-engine calls. Its Appendix H varies the number of sampled trajectories per question during GRPO training. The curious result is that group size one scores 0.410 on average across seven QA sets, ahead of size three (0.363) and size five (0.350).

But how can a group-relative algorithm learn from a group of one?

The apparent contradiction

In outcome-based GRPO, a group of \(G\) responses to the same question receives rewards \(r_1,\ldots,r_G\). A common advantage is the reward centered and scaled within that group:

\[ \hat A_i=\frac{r_i-\bar r}{s_r+\varepsilon}, \qquad \bar r=\frac{1}{G}\sum_{j=1}^{G}r_j. \]

Set \(G=1\). Then \(\bar r=r_1\), so the numerator is zero. The usual sample standard deviation is also undefined for a singleton. Adding \(\varepsilon\) to the denominator can avoid division by zero, but it cannot restore a learning signal: \(\hat A_1=0\). Naively substituting \(G=1\) into group-normalized GRPO does not yield REINFORCE.

What the released Search-R1 code actually does

The paper explicitly says that size one becomes REINFORCE. The released implementation makes that possible with a special case in compute_grpo_outcome_advantage:

if len(id2score[idx]) == 1:
    id2mean[idx] = torch.tensor(0.0)
    id2std[idx] = torch.tensor(1.0)

The same function then computes (score - mean) / (std + epsilon). Thus a single trajectory uses

\[ \hat A_1=\frac{r_1-0}{1+\varepsilon}\approx r_1, \]

not the zero advantage implied by within-group centering. The trainer passes these advantages into the policy update. The public GRPO path calls this function; the released training script sets algorithm.adv_estimator=grpo and rollout.n_agent=5 for its default group-size-five run.

This is a REINFORCE-like reward weight inside a PPO-style clipped policy update with KL regularization, not an exact switch to a standalone vanilla REINFORCE trainer. The code demonstrates the special-case estimator; it does not by itself document the exact seeds and checkpoints used for Appendix H.

How a raw reward learns without comparing siblings

Consider a two-answer policy. Its probability of producing the correct answer is \(p=\sigma(z)\), with reward one for correct and zero for incorrect. With a raw-reward policy gradient,

\[ \mathbb E\!\left[r\,\frac{\partial}{\partial z}\log\pi_z(a)\right] =p(1-p). \]

A correct sample has a positive update; an incorrect sample has zero reward-driven update. Averaged over sampling, the gradient still increases \(p\) for \(0<p<1\). Negative examples need not receive explicit negative advantages for learning to occur. In Search-R1, the separate KL and entropy-related terms can still act even when the outcome reward is zero.

The key change is the estimator, not a magical property of one-sample groups:

What the group-size result actually shows

The size-one run is 6.0 percentage points above size five. The paper also reports that larger groups learn faster on the training curve, while some runs become unstable. Models are evaluated from the final checkpoint when training remains stable, or from a previous stable checkpoint when it collapses.

This is not a clean test of group size alone. At \(G=1\), the algorithm uses raw rewards instead of relative, standardized advantages. Group size can also change the number and distribution of trajectories processed, while different checkpoint choices affect the reported score. Appendix H does not provide variance across random seeds. It therefore cannot establish that one rollout is intrinsically better for generalization.

What I would test next

Hold the model, questions, total rollout budget, optimizer, KL coefficient and checkpoint-selection rule fixed. Then compare: (a) raw-reward advantage at \(G=1\), (b) raw-reward advantage at larger \(G\), and (c) centered group advantages at larger \(G\). Report both the rate of all-equal-reward groups and the variance of gradient estimates, across multiple seeds.

That separates two questions the current table mixes: how many trajectories should be sampled for a question? and which baseline should convert their rewards into updates? The second question is at least as important as the first.

Limits

This note checks the paper's Appendix H against the released estimator and derives a small two-action example. I did not reproduce its 7B training runs, and the public code does not verify which exact run produced each appendix checkpoint. The numerical comparison is the authors' result, not mine.

Takeaway

Search-R1's \(G=1\) result is not a paradox. The one-sample branch stops computing a group-relative advantage and uses the outcome reward itself. The interesting open question is whether the better score comes from that estimator, the rollout budget, training stability, or checkpoint selection—not from the number one by itself.
